# 启动项管理

双击 `Open365.exe` 打开启动项管理；`--open home` 仍可直达电脑体检，`--tray` 只常驻托盘。

## 日常操作

1. 顶部查看已启用、已禁用和可按需关闭的数量。
2. 输入程序名称、路径或来源筛选，或切换状态标签。
3. 选择一行，底部查看完整命令、快捷方式的目标与参数。文本可复制。
4. 点击「禁用自启」或「恢复自启」。禁用保留原项备份，恢复时拒绝覆盖同名项。
5. 点击「新增自启」，选择 `.exe`、`.com`、`.bat` 或 `.cmd`，填写名称；参数可以留空。添加的是当前用户登录时运行的快捷方式，不立即执行程序。

列表当前覆盖注册表 Run 和用户/公共启动文件夹，**不含计划任务、服务和商店应用**。
建议仅按本地名称与路径匹配，不是性能测量或安全鉴定。无法确定的项目显示「需要你判断」。
当前版本没有解析 Windows `StartupApproved` 状态；被任务管理器或其他工具禁用的项，
可能与这里显示的状态不同。此类项目应先在 Windows 启动应用设置中核对。

## 机器调用

所有 GUI 写操作都调用 `core/action-core.ps1`，新增能力为 `startup.add`。
输入 JSON 写入文件，避免命令行转义丢失参数：

```json
{
  "name": "我的程序",
  "target_path": "C:\\Program Files\\Example\\Example.exe",
  "arguments": "--profile \"work profile\""
}
```

```powershell
powershell -NoProfile -File core/action-core.ps1 run startup.add -InputFile input.json -Confirm -Json
```

新增、启用和禁用都经过确认闸门；`OPEN365_SANDBOX=1` 时禁止写入。
新增动作写当前用户的启动文件夹，不要求管理员；切换现有项的权限由引擎按目标判断。
`startup.disable` 可取消新增项的自启，但会保留快捷方式备份。

## 回归验证

```powershell
powershell -NoProfile -File tests/test-startup-workspace.ps1
powershell -NoProfile -File tests/test-startup-ui.ps1
```

第一条在随机测试注册表键和临时文件夹验证新增、禁用、恢复、冲突拒绝、
参数保真和确认闸门，不改真实启动项。第二条使用真实 WinForms 控件和固定演示数据，
验证搜索、筛选、排序后详情、加载状态、小窗口及 150% 缩放，并在 `artifacts/startup-ui/` 保存界面图。
