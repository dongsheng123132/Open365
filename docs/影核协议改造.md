# Open365 × 影核协议（ActionParity ShadowCore）

一句话：**GUI 按钮、CLI 命令、AI 调用，从今天起指向同一个动作。**

标准正文见 [ActionParity](https://github.com/dongsheng123132/action-parity)
与 [影核协议中文版](https://github.com/dongsheng123132/action-parity/blob/main/docs/SHADOW-SYNC.zh-CN.md)。

## 为什么做这件事

Open365 有 GUI，也有引擎 CLI。过去这两条路是各写各的：GUI 自己拼
`engine\*.ps1` 命令行、自己解析 JSON、自己判断成败。带来的老问题是：

- **GUI 没法稳定自动化测试。** 要验证"体检按钮到底有没有跑对"，只能截图、
  找控件、点鼠标——慢、脆、还会被分辨率和主题影响。
- 引擎输出改一个字段，GUI 可能默默读到 `null`，没有任何东西会报警。
- AI 想用 Open365，只能去读源码猜命令行。

影核协议把这件事拆开：**"软件做没做对"用动作核心验证，"人点不点得到"才用真
实 GUI 验证。** 于是绝大多数回归可以无界面、秒级、AI 自己跑完。

## 现在的结构

```text
GUI 按钮 ─┐
CLI 命令 ─┼──> core/action-core.ps1 ──> engine/<单一规范实现>.ps1
AI/自动化 ┘         │
                    ├─ 输入校验（不合法 0 毫秒拒绝，不进引擎）
                    ├─ 权限闸门（非只读动作默认拒绝）
                    ├─ 输出契约校验（引擎漂移当场暴露）
                    └─ 稳定 JSON 信封 + 语义化退出码
```

依赖方向只有一条：**core → engine**。引擎之间依旧零引用，引擎也不知道动作核心
存在——`docs/架构约定.md` 的三条铁律一条没破。

- `core/registry.ps1` —— 动作注册表，**唯一真相源**（动作 ID、输入输出 Schema、
  风险等级、超时、各界面绑定）。
- `core/action-core.ps1` —— 发现 / 校验 / 闸门 / 执行 / 自证。
- `action-parity.json` —— 由注册表生成的公开清单，**不要手改**；改了会被测试抓到。

## 已同源的动作（第一批）

| Action ID | 类别 | GUI 绑定 | 说明 |
|---|---|---|---|
| `security.check` | read | `Open365.Gui.SecurityCheck` | 三道防线体检 |
| `network.diagnose` | read | `Open365.Gui.NetworkDiagnose` | 网络体检 |
| `cleaner.scan` | read | `Open365.Gui.CleanerScan` | 垃圾扫描（只扫不删） |
| `startup.list` | read | `Open365.Gui.StartupList` | 开机启动项列表 |
| `startup.disable` | write | `Open365.Gui.StartupToggle` | 可还原（回滚动作 `startup.enable`） |
| `startup.enable` | write | `Open365.Gui.StartupToggle` | `startup.disable` 的回滚 |
| `process.list` | read | `Open365.Gui.ProcessList` | 进程列表 |
| `software.search` | read | `Open365.Gui.SoftwareSearch` | 按关键词搜已安装软件 |
| `software.list` | read | `Open365.Gui.SoftwareList` | 全部已安装软件 |
| `focus.status` | read | *（一致性例外）* | 读电源超时 |

尚未纳入的功能（清理执行、卸载、残留清理、网络修复、快速查杀等）仍走旧路径，
语义不变。这是刻意的：影核协议要求**先切一小片跑通**，不是一次性重写。

### 一条诚实的一致性例外

`focus.status` 在清单里带 `parity_exceptions`：GUI 的守夜模式是在
`gui/Open365Tray.cs` 里进程内实现的，和 `engine/focus.ps1` 是**两份同语义代码**。
标准不允许假装它们同源，所以把它写成了带负责人和复查日期的显式例外，
而不是悄悄让绑定检查通过。

## 给 AI / 自动化用

```powershell
# 有哪些动作
powershell -File core\action-core.ps1 list -Json

# 契约长什么样（不用读源码）
powershell -File core\action-core.ps1 describe security.check -Json

# 执行（只读动作随便跑）
powershell -File core\action-core.ps1 run security.check -Json

# 带输入
powershell -File core\action-core.ps1 run software.search -InputJson '{"query":"chrome"}' -Json

# 无头自测：清单 + 各界面绑定 + 全部只读动作 + 默认拒绝
powershell -File core\action-core.ps1 verify -Json
```

约定：

- stdout 只有单行 JSON 信封，stderr 放诊断；
- 退出码 `0` 成功 / `1` 失败 / `2` 用法错误 / `3` 被权限闸门拒绝；
- 改系统的动作**默认拒绝**，必须显式 `-Confirm`；
- `OPEN365_SANDBOX=1` 时一切非只读动作直接拒绝——AI 无人值守跑回归时请打开它。

### 三个必须知道的坑（都是实测踩出来的）

1. **必须用 `-File` 调用。** `powershell -Command "& '<脚本>'"` 会把脚本退出码
   压成 1，语义化退出码（2 / 3）只有 `-File` 才透传。
2. **含引号的 JSON 别直接当参数传。** PowerShell 之间传参会重新解析，
   写临时文件走 `-InputFile` 才稳（GUI 与测试都是这么做的）。
3. **输出编码由脚本自己钉死。** 中文 Windows 控制台是 GBK，早期版本被 `-File`
   直接调用时输出的 JSON 无法按 UTF-8 解析。现在动作核心和所有引擎开头都强制
   `[Console]::OutputEncoding = UTF8`，调用方按 UTF-8 读即可。

## 无头测试

```powershell
powershell -File tests\test-action-parity.ps1     # 11 项契约测试
powershell -File tests\run-all.ps1                # 已包含上面这项
```

测的是：清单没漂移、每条界面绑定都指向同一 Action ID（静态检查，不开窗口）、
每个只读动作真的能无界面跑通且输出符合 Schema、非法输入被拒、写动作默认被拒、
沙箱模式生效、动作核心与旧引擎命令返回同一组字段。

**真实 GUI 仍然要测**，但只剩下"人能不能看到、够得着、看得懂"：按钮可见、
焦点顺序、高 DPI、深色模式。业务回归不再藏在 UI 自动化的抖动后面。

## 改造中抓到的真实缺陷

上线第一次跑 `verify` 就抓到一个：`uninstall.ps1` 在搜不到软件时输出
`"apps": null` 而不是 `[]`，GUI 会当成"读取失败"。这类问题正是过去没有输出契约
时会长期潜伏的。已在引擎里修好（一律 `@()` 包住）。

## 加新功能时（补充 docs/架构约定.md）

1. 照旧新建 `engine/<名字>.ps1`，自洽 CLI、默认只读、支持 `-Json`；
2. 在 `core/registry.ps1` 注册一个动作（ID、Schema、风险、绑定）；
3. GUI 里调 `Program.RunAction("<id>", ...)`，并给控件设稳定的
   `Name` / `AccessibleName`；
4. 跑 `powershell -File core\action-core.ps1 manifest -WriteManifest` 更新清单；
5. 跑 `powershell -File tests\test-action-parity.ps1` 必须全绿。

## 当前符合性边界

只声明 **AP-1 / AP-2**：动作可发现、有 Schema、可无界面执行与测试；GUI 与 CLI
必需绑定调用同一动作核心。

不声明 AP-3（缺完整审计与取消/进度事件）与 AP-4（缺已发布的真实 GUI 旅程与
无障碍报告）。官方验证器当前结果：动作 10 个，无头 10/10，必需绑定 19/20
（差的一条是上面那条显式例外），错误 0，警告 0。
